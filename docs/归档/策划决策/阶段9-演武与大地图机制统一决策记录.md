## 1. 背景与问题

### 1.1 现状（经代码核实，修正 v1 错误描述）

| 层 | 大地图（战略） | 演武（战术） | 问题 |
|:---|:---|:---|:---|
| 管理器 | `StrategicMapManager` | `TacticalSkirmishManager` | 双份单位/移动/攻击逻辑 |
| 单位伤害 | **已调用** `CombatResolver.compute_damage`，但 **atk/def ctx 为空** | 完整 ctx（科技/学派/大夫/粮荒等） | 同公式不同输入 → 数值不一致 |
| 攻击阶段 | 仅单次伤害；**无**反击/夹击/火攻 | 完整管线（`skirmish_attack_pipeline`） | 大地图缺反制与 DOT |
| 攻城 | **简化式** `atk × siege_mult × 20/(20+def)` | 城墙结构 HP、器械倍率、驻军反击 | 攻城难度不可比 |
| 移动 | Dijkstra，无 ZOC/遮挡 | ZOC、搁浅、远程遮挡、城墙挡格 | 机动规则分裂 |
| 士气 | 字段存在，几乎不结算 | 四段式 + 夹击/包围/断粮 | 大地图士气形同虚设 |
| 单位字段 | `mp/max_mp/count/col/row` | `speed/mp_remaining/skills/is_supplied/burn_*` | 命名与字段集不一致 |
| AI | `StrategicAI`：残血优先、预算≤5、只打战争目标 | `SkirmishAI`：随机移动+随机目标 | 教学关与主图行为分裂 |
| 建造 API | `can_build/start_build` 支持可选 `axial`（U-1 已修） | 放置 UI 3 参调用 | 曾撕裂；契约需写死 |

**结论**：不是「从零抽出伤害公式」，而是 **补齐 ctx 组装 + 攻击阶段机 + 攻城结构 + UnitState 命名统一**。

### 1.2 设计原则（用户确认，2026-09-17 收紧定稿）

> **演武 = 大地图的局部场景**  
> **基础玩法必须完全统一（零差异）**：战斗、攻城、地形、移动、建筑战斗效果、UnitState、战斗 AI 评分、建造 API——同一套程序、同一套 `data/*.json`、同一套公式。  
> **仅文化、外交等可简化**，且简化项必须相对独立，不得反向污染战斗/移动/攻城内核。  
> 完整经营回合（税收/人口/科技回合等）与写回策略属流程层，不在演武内模拟；若演武内建造，API 与大地图相同。

**禁止**：以「切片」为由在基础玩法上另写简化公式；禁止第二套墙 HP/地形/ZOC/伤害结算。

### 1.3 目标

1. 同一兵种在大地图与演武中数值、手感一致  
2. 修一处 bug 两边同时受益  
3. 存档单位状态单一 schema（schema_version 3）  
4. AI 战斗评分共用；战略流程约束（宣战/预算）留在适配层  
5. 单一真相源：机制以 `docs/机制概览/` 为准，不以程序反推  
6. **审核标准**：对照《演武与大地图统一规范》§1.1 / §11

## 2. 关键决策

### 决策 210：统一内核范围（修正 v1）

**必须统一**：

| 模块 | 内容 | 说明 |
|:---|:---|:---|
| **CtxBuilder** | 攻/防修正组装（科技/学派/大夫/粮荒/士气/地形） | 禁止两边各拼一套 |
| **CombatPipeline** | 预检后的结算：伤害→反击→夹击/包围士气→火攻 DOT | 从演武管线抽出 |
| **MovementReach** | 地形、ZOC、远程遮挡、城墙挡格、搁浅 | 以演武为基准 |
| **SiegeResolver** | 城墙结构 HP、器械倍率、驻军反击、占城 | 演武结构 + CityManager |
| **UnitState** | 统一字段与序列化 | 见决策 215 |
| **Building API** | `can_build/start_build` 单入口 | 见决策 214 |
| **AI Scoring** | 目标分、残血、器械优先、ZOC 风险 | 见决策 217 |

**不统一（场景适配层保留）**：

- 阵营/宣战/acted/距离 **预检**（大地图 `are_at_war` 门闩必须保留，不进纯内核）
- 地图边界、写回策略、UI、回合来源

### 决策 211：场景差异表（补充）

| 差异项 | 大地图 | 演武 | 归属层 |
|:---|:---|:---|:---|
| 地图范围 | 全图 | 场景切片 | 数据 |
| 宣战门闩 | `are_at_war` 必须 | 场景预设敌对，跳过 | **适配层预检** |
| 中立城 | AI 不打中立；玩家可攻中立 | 场景规则 | 适配层 |
| UI 反馈 | 需墙 HP/反击/士气显示（U5） | 已有 | 场景 UI |
| 写回 | 直接 | Demo 可选 | 流程策略 |
| `count` 多兵员 | 参与伤害（见 215） | 单体/编队按场景 | UnitState |

### 决策 212：文化 — 只读查询，不落快照字段

**选定**：演武**不**跑文化扩散；需要时 **只读** `CityManager.get_mainstream_culture` / `has_culture_mismatch`。

- 不拷贝文化字典、不新增演武侧 culture 状态字段  
- mismatch 若进战斗，仅通过 **def ctx** 注入，由 CtxBuilder 负责  
- HUD 展示可缓存显示值，不参与存档  

**理由**：现状演武与文化耦合为零；快照会引入第二份状态。只读函数已存在。

### 决策 213：外交 — 不跑外交 AI；修正一律经 CtxBuilder 实时只读

**选定**：

| 项 | 大地图 | 演武 |
|:---|:---|:---|
| 外交 AI/宣战/停战 | 完整 | **不跑** |
| 进场阵营 | 运行时 | 场景预设 |
| 宣战门闩 | 是 | 否（已预设敌对） |
| 科技/学派/大夫/粮荒/国力士气 | 权威源 | **CtxBuilder 实时只读**（非进场一次快照） |
| 写回外交 | — | 默认不写回 |

**Demo 例外**：洛邑胜利 → `DemoFlow.apply_skirmish_victory` → `CityManager.change_ownership`；**不**改条约。U7 必须回归 `test_main_turn_ui`。

**理由**：演武管线现已实时读 Tech/学派/大夫；「进场快照」会与现网冲突且增加同步 bug。

### 决策 214：建造 API 契约（升为前置，U-1）

**签名**（已实现，写死契约）：

```
can_build(city_id, building_id, axial: Vector2i = Vector2i(-9999,-9999)) -> Dictionary
start_build(city_id, building_id, axial: Vector2i = Vector2i(-9999,-9999)) -> bool
```

**Reason 契约**：`OK` / `INVALID_CITY` / `INVALID_BUILDING` / `ALREADY_BUILT` / `ALREADY_QUEUED` / `SLOTS_FULL` / `NATIONAL_CAP_REACHED` / `INSUFFICIENT_RESOURCES` / **`HEX_OUT_OF_JURISDICTION`** / **`HEX_OCCUPIED`**

**规则**：指定 axial 时校验辖区+占用；队列写入 `hex_q/hex_r`（odd-R）；未指定则完工时自动分配。

**消费方**：城池面板、大地图放置 UI、EconomyAI、未来演武内放置。

### 决策 215：UnitState 字段权威（修正 v1）

**命名规则**：**序列化与对外 API 统一用 `mp` / `max_mp`**；演武内部若保留 `mp_remaining` 仅作兼容别名，迁移后废弃。

**最小权威字段**：

```
id, faction_id, unit_type_id
q, r                    # axial
col, row                # odd-R，可选，便于地图对齐
hp, max_hp
mp, max_mp              # 演武 speed → 迁移为 mp
morale
count                   # 大地图多兵员；伤害缩放见下
acted
skills: Array           # 默认 []
is_supplied: bool       # 默认 true
attacks_this_turn: int  # 默认 0
burn_turns, burn_damage
stranded_turns
flanking_penalty        # 或由管线临时算，二选一写死：存字段
```

**`count` 语义**：大地图 `count>1` 时，伤害对目标按编队 HP 池结算；演武默认 `count=1`。不得在管线外再乘一套系数。

**schema_version**：`2 → 3`；加载时旧档补默认字段、**不删**未知字段；`>3` 拒绝。

### 决策 216：架构边界

```
适配层（Manager）          纯内核（systems/）
- 阵营/宣战/acted/距离预检  - CtxBuilder
- 写回 CityManager         - CombatPipeline
- 场景边界/预算            - MovementReach
- UI 信号                  - SiegeResolver
                           - UnitState schema
```

**禁止**：Manager 内再写第二套 `compute_*` 伤害/攻城公式。

**数据驱动**：攻城系数、反击、墙防、火攻季节等 **只**从 `balance_params.json` / `terrain.json` / `units.json` 读；新 pipeline 内禁止硬编码数值。

### 决策 217：AI 统一 + 演武难度档

**选定**：

- `ai_combat_scoring.gd`：目标评分、残血优先、器械攻城、ZOC 风险  
- `StrategicAI`：调用评分 + 预算 + 战争过滤  
- `SkirmishAI`：场景 `ai_mode`：  
  - `tutorial`（默认教学关）：弱化/引导  
  - `random`：现网随机  
  - `scored`：完整评分  

避免教学关被完整 AI 打爆。

### 决策 218：性能

- 大地图 AI 保持每回合单位预算（现 ≤5）  
- `detail_level` **不进默认设计**；仅当剖析超阈值时作应急开关  
- 共享内核保持纯函数、无场景 IO
