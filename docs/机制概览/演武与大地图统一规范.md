# 演武与大地图统一规范

> 本文档是**机制权威**：定义演武（战术切片）与大地图（战略主图）如何共享同一套基础玩法。  
> 决策依据：`docs/归档/策划决策/阶段9-演武与大地图机制统一决策记录.md`  
> 所有数值从 `data/*.json` 读取，禁止硬编码。  
> **修订**：2026-09-17 按策划确认原则收紧——**基础玩法零差异**。

---

## 1. 设计原则（策划定稿）

> **演武 = 大地图的局部场景，不是另一套游戏。**

### 1.1 基础玩法：必须完全统一（零差异）

下列机制在大地图与演武中必须是：

- **同一套程序实现**（共享内核，禁止第二套 `compute_*`）
- **同一套数据**（`data/*.json`，同一 `balance_params` / `buildings` / `terrain` / `units`）
- **同一套公式与阶段顺序**（伤害、反击、士气、火攻、攻城、移动、ZOC、地形修正）

| 基础玩法模块 | 统一要求 |
|:---|:---|
| 单位战斗（伤害/克制/反击/夹击/包围/士气/火攻） | 完全相同 |
| 攻城（器械倍率、墙城 HP、伤害分流、城防反击、占城判定） | 完全相同 |
| 地形（移动力、攻击/防御修正、天堑、骑兵/水军限制、高程与射程） | 完全相同 |
| 移动（Dijkstra、ZOC 额外消耗、城墙挡格、远程遮挡） | 完全相同 |
| 建筑战斗效果（墙 structure_hp、defense_bonus、箭塔 tower_attack 等） | 完全相同 |
| 单位状态字段（UnitState v3：hp/mp/morale/skills/…） | 完全相同 |
| 战斗向 AI 评分（选目标、残血、器械对城） | 完全相同（见 §8） |
| 建造 API 与辖区（若在演武内放置） | 完全相同（CityManager 单入口） |

**禁止**：以「演武是切片」为由，在基础玩法上另写简化公式、另一套墙 HP 规则、另一套地形判定。

### 1.2 允许简化的系统（必须彼此独立）

仅下列系统允许在演武侧**简化或不跑**；且简化项之间、简化项与基础玩法之间应尽量**解耦**，不得反过来污染战斗/移动/攻城公式：

| 系统 | 演武侧 | 独立性要求 |
|:---|:---|:---|
| **文化** | 不跑扩散/主流变更；需要时**只读**权威源 | 不得写进移动/伤害公式的第二套逻辑；若进战斗只经 CtxBuilder 注入 |
| **外交** | 不跑外交 AI/条约结算；进场敌对由场景预设 | 宣战门闩属大地图流程预检，**不得**写进纯内核伤害函数 |
| **完整经营回合** | 不跑税收/人口/科技回合/灾害结算等「一整轮国家模拟」 | 与战斗内核无关；演武内若建造，API 与大地图相同 |
| **写回策略** | 默认不写主存档；Demo 可按规则写回占城等 | 流程策略，不改变公式 |

> **一句话**：文化/外交/整轮经营/写回策略可以「演武不做」；  
> **战斗、攻城、地形、移动、建筑战斗效果不可以「演武另一套」。**

### 1.3 场景适配层只允许做的事

| 允许 | 不允许 |
|:---|:---|
| 地图范围（全图 vs 切片） | 另一套伤害/攻城/移动公式 |
| 预检流程（宣战门闩、场景敌对） | 把简化公式写进 Manager 私有函数并绕过内核 |
| UI / 特效 / 日志 | 另一套墙 HP 结算规则 |
| AI 行动预算、教学引导档位 | 改变地形移耗或 ZOC 定义 |
| 存档范围（是否入主存档） | 与 `data/*.json` 不一致的硬编码数值 |

## 2. 架构分层

```
┌──────────────────────────────────────────────────────┐
│  共享内核 scripts/systems/（基础玩法唯一实现）          │
│  · unit_state                 单位状态 schema        │
│  · combat_ctx_builder         攻/防修正组装          │
│  · combat_resolver            伤害/反击/克制          │
│  · movement_reach             可达/ZOC/射程          │
│  · siege_resolver + wall_combat_rules  攻城/墙城     │
│  · building_combat_effects    建筑战斗效果            │
│  · ai_combat_scoring          战斗目标评分            │
└──────────┬───────────────────────────┬───────────────┘
           │                           │
    ┌──────▼──────┐             ┌──────▼──────┐
    │ 大地图适配层  │             │ 演武适配层    │
    │ StrategicMap │             │ TacticalSkirmish│
    │ · 宣战门闩   │             │ · 场景预设敌对 │
    │ · 全图/UI    │             │ · 切片/UI     │
    │ · 写回城池   │             │ · Demo 写回   │
    └─────────────┘             └─────────────┘
```

**禁止**：在任一 Manager 内再写第二套 `compute_*` 伤害/攻城/移动公式。

## 3. UnitState（单位状态权威 schema）

### 3.1 字段

| 字段 | 类型 | 说明 |
|:---|:---|:---|
| `id` | String | 场景内唯一 |
| `faction_id` | String | 归属势力 |
| `unit_type_id` | String | `units.json` |
| `q`, `r` | int | axial 坐标 |
| `col`, `row` | int | odd-R 偏移（可选，地图对齐） |
| `hp`, `max_hp` | int | 生命 |
| `mp`, `max_mp` | int | 行动力（演武旧名 `speed`/`mp_remaining` 仅为兼容别名） |
| `morale` | int | 0~130，四段式见《战斗系统》 |
| `count` | int | 编队人数；演武默认 1，规则与大地图同一 HP 池 |
| `acted` | bool | 本回合是否已行动 |
| `skills` | Array | 兵种/将领技能 |
| `is_supplied` | bool | 是否有补给 |
| `attacks_this_turn` | int | 本回合攻击次数 |
| `burn_turns` / `burn_damage` | int | 火攻 DOT |
| `stranded_turns` | int | 搁浅 |
| `flanking_penalty` | int | 夹击/包围惩罚 |

### 3.2 规则

1. 序列化与对外 API 一律 `mp` / `max_mp`（schema_version = 3）  
2. 旧档补默认字段，**不删除**未知字段  
3. `count > 1`：HP 池编队结算，**禁止**管线外另乘人数系数

## 4. CtxBuilder（修正组装）

### 4.1 必须进入统一组装的来源

| 来源 | 攻 | 防 | 查询 API（只读） |
|:---|:---:|:---:|:---|
| 地形 | ✓ | ✓ | `terrain.json` atk_mod / def_mod |
| 科技 | ✓ | ✓ | `TechSystem` |
| 学派 | ✓ | ✓ | `SchoolManager` |
| 武大夫 | ✓ | ✓ | `MinisterManager` |
| 国家民心 | ✓ | — | `GameManager` |
| 粮荒 | ✓ | ✓ | `GameManager` |
| 单位被动技能 | ✓ | — | UnitState.skills |
| 火攻/伏击 | ✓ | — | 季节 + 地形 |
| 单位士气四段 | ✓ | ✓ | `CombatResolver` |
| 建筑战斗效果（城防等） | — | ✓ | `BuildingCombatEffects` |
| 文化 mismatch（若启用） | — | ✓ | 只读 CityManager，经 def ctx |

### 4.2 规则

1. 大地图与演武必须调用**同一 CtxBuilder**  
2. 权威源在大地图/全局系统；演武只读，不另建快照公式  
3. 禁止 Manager 手拼第二套 ctx  
4. 生产路径必须传 ctx；空 ctx **仅**允许单元测试

## 5. CombatPipeline（攻击阶段机）

### 5.1 阶段顺序（两边相同）

```
预检（适配层） → 伤害 → 反击 → 夹击/包围士气 → 火攻 DOT → 状态写回
```

| 阶段 | 内容 | 归属 |
|:---|:---|:---|
| **预检** | 同阵营/acted/距离/射程/MP | 适配层 |
| **宣战门闩** | 仅大地图流程需要 `are_at_war` | 适配层，**不进内核** |
| 伤害 | `CombatResolver.compute_damage` + ctx | 内核 |
| 反击/士气/火攻 | 见《战斗系统》 | 内核 |
| 写回 | hp/morale/burn/acted/mp | 适配层 |

### 5.2 输出结构

```
{ ok, reason, damage, counter_damage?, fire?, morale_delta_atk?, morale_delta_def? }
```

## 6. MovementReach（可达格）

两边共用，因素**完全一致**：

| 因素 | 说明 |
|:---|:---|
| 地形 `move_cost` | 天堑未解锁为不可达 |
| 骑兵/水军限制 | `cavalry_allowed` / `is_navigable` |
| ZOC | 敌方控制区额外消耗（同一 `zoc.*` 参数） |
| 远程遮挡 | 高程差减射程（同一 `MovementReach.effective_range*`） |
| 城墙挡格 | 未破墙不可通行/停留 |
| 搁浅 | 水域规则 |
| MP | 本回合剩余行动力（UnitState.mp） |

地图边界由适配层裁剪；**不得**用另一套移耗表。

## 7. 攻城与城墙（基础玩法，必须相同）

### 7.1 统一规则

| 规则 | 实现 | 数据 |
|:---|:---|:---|
| 器械倍率 | `WallCombatRules.siege_multiplier` | `city_combat.siege_damage_multiplier` |
| 墙/城伤害分流 | `WallCombatRules.split_damage_to_wall` | `city_combat.damage_split_wall` + `wall_struct_def_by_level` |
| 城防加成 | `WallCombatRules` / `BuildingCombatEffects.city_building_def_buff` | 墙 HP 比例 + 建筑 `defense_bonus` |
| 墙结构 HP | `buildings.json` wall `structure_hp` | 同一建筑表 |
| 箭塔 | `arrow_tower.tower_attack` | 同一建筑表 |
| 占城 | 墙/城 HP 归零 + 适配层 `CityManager.change_ownership` | 同一 CityManager API |

### 7.2 运行时状态：统一语义，允许「同一数据的场景缓存」

| 项 | 要求 |
|:---|:---|
| **公式与字段语义** | 两边完全一致（structure_hp、defense_bonus、分流比例） |
| **权威存储** | `CityManager` 城池建筑（入主存档） |
| **演武场景** | 若场景绑定 `city_id`，建筑效果**从 CityManager 读取**；战斗中墙损写在场景缓存 |
| **写回** | 属 §1.2 写回策略；**不**因写回与否而改变攻城公式 |

> 「场景缓存」≠「另一套机制」。审核标准是：**同一公式、同一建筑数据语义、同一 JSON 系数**。

### 7.3 中立城

- 大地图：玩家可攻中立；AI 默认不攻中立（战略策略）  
- 演武：按场景配置单位与敌对；**若发生攻城，公式与大地图相同**

## 8. AI（战斗向统一；战略流程可分层）

| 层 | 要求 |
|:---|:---|
| **战斗目标评分** | 必须用 `AiCombatScoring`（残血、近距、器械对城） |
| **tutorial 档** | 仅削弱「追杀强度/引导」，**不得**改伤害/移耗/墙城公式 |
| **random 档** | 仅测试兼容；不得作为正式内容默认 |
| **大地图战略 AI** | 额外约束：宣战过滤、每回合行动预算——属流程，不属战斗公式 |

## 9. 文化与外交（允许简化，且独立）

| 系统 | 演武行为 | 独立性 |
|:---|:---|:---|
| 文化扩散/主流变更 | **不跑** | 不进移动/伤害第二套逻辑 |
| 文化 mismatch | 只读权威源；进战斗只经 def ctx | 经 CtxBuilder，不旁路 |
| 外交 AI/条约 | **不跑** | 不进内核 |
| 宣战检查 | 场景预设敌对 | 适配层预检 |
| 科技/学派/大夫/粮荒 | CtxBuilder **实时只读** | 与大地图同一数据源 |
| Demo 占城写回 | 可选策略 | 不改公式 |

## 10. 建造 API（经营入口，统一）

```
can_build(city_id, building_id, axial = Vector2i(-9999,-9999))

get_jurisdiction_hexes(city_id)  # 视觉辖区环，轴向
```

- 城池面板、大地图放置、演武内放置、EconomyAI **同一入口**  
- 辖区、占用、reason 契约见《城市经营》

### 11.2 仍须收敛的基础玩法差异（**不是**「允许差异」）

| # | 差异 | 要求 | 状态 |
|:---|:---|:---|:---|
| G1 | 演武墙损默认**不写回** CityManager | 写回策略可简化，但场景绑定 `city_id` 时，战斗中建筑效果读数必须与大地图同源；可选「战斗结束同步墙损」 | ⏳ 策略待定，公式已统一 |
| G2 | 演武未跑大地图「单位编队 count 大池」的全部战略结算 | 同一 UnitState/伤害池规则；场景 count=1 时行为一致 | ✅ 规则一致 |
| G3 | 战略 AI 含行军/预算，演武无 | **允许**（流程层）；战斗选目标必须同一评分库 | ✅ 评分已统一 |
| G4 | `ai_mode=random` | 正式场景应默认 `scored`/`tutorial`，random 仅测试 | ⏳ 场景表待收 |
| G5 | 演武技能改移耗的适配分支 | 技能效果必须叠加在 **同一** MovementReach 地形/ZOC 结果上，不得替换地形表 | ✅ 已叠在共享 reach 上 |
| G6 | 文化/外交/整轮经营不跑 | **允许**（§1.2），保持独立 | ✅ 按设计 |
