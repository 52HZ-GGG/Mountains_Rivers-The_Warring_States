# 演武与大地图统一规范

> 本文档是**机制权威**：定义演武（战术切片）与大地图（战略主图）如何共享同一套战斗/移动/经营规则。  
> 决策依据：`docs/归档/策划决策/阶段9-演武与大地图机制统一决策记录.md`  
> 所有数值从 `data/*.json` 读取，禁止硬编码。

---

## 1. 设计原则

> **演武 = 大地图的局部场景。**

1. **战斗、移动、攻城、单位状态、AI 评分、建造 API** 必须同一套程序实现  
2. 场景差异只允许存在于：地图范围、预检门闩、UI、写回策略  
3. **文化 / 外交** 在演武侧 **只读**，不跑扩散、不跑外交 AI、不写回条约  
4. 机制以本系列文档为准，不以程序实现反推  

---

## 2. 架构分层

```
┌─────────────────────────────────────────────┐
│  共享内核 scripts/systems/（纯函数，无场景 IO） │
│  · UnitState        单位状态 schema          │
│  · CtxBuilder       攻/防修正组装            │
│  · CombatPipeline   伤害→反击→士气→火攻      │
│  · MovementReach    可达格                   │
│  · SiegeResolver    城墙/攻城                │
│  · AI Scoring       目标与攻击评分            │
└──────────┬──────────────────┬───────────────┘
           │                  │
    ┌──────▼──────┐    ┌──────▼──────┐
    │ 大地图适配层  │    │ 演武适配层    │
    │ StrategicMap │    │ TacticalSkirmish│
    │ · 宣战门闩   │    │ · 场景预设敌对 │
    │ · 写回城池   │    │ · 教学 UI     │
    │ · 全图预算   │    │ · Demo 写回   │
    └─────────────┘    └─────────────┘
```

**禁止**：在任一 Manager 内再写第二套 `compute_*` 伤害/攻城公式。

## 3. UnitState（单位状态权威 schema）

### 3.1 字段

| 字段 | 类型 | 说明 |
|:---|:---|:---|
| `id` | String | 场景内唯一 |
| `faction_id` | String | 归属势力 |
| `unit_type_id` | String | `units.json` |
| `q`, `r` | int | axial 坐标 |
| `col`, `row` | int | odd-R 偏移（可选，地图对齐） |
| `hp`, `max_hp` | int | 生命 |
| `mp`, `max_mp` | int | 行动力（演武旧名 `speed`/`mp_remaining` 迁移为本字段） |
| `morale` | int | 0~130，四段式见《战斗系统》 |
| `count` | int | 编队人数；演武默认 1 |
| `acted` | bool | 本回合是否已行动 |
| `skills` | Array | 兵种/将领技能，默认 `[]` |
| `is_supplied` | bool | 是否有补给，默认 true |
| `attacks_this_turn` | int | 本回合攻击次数，默认 0 |
| `burn_turns` | int | 火攻剩余回合 |
| `burn_damage` | int | 每回合灼烧伤害 |
| `stranded_turns` | int | 搁浅剩余回合 |
| `flanking_penalty` | int | 当前夹击/包围士气惩罚（或由管线临时算，序列化时写入） |

### 3.2 命名与迁移

- **序列化与对外 API 一律使用 `mp` / `max_mp`**  
- 演武内部若仍读 `mp_remaining`，仅作兼容别名，迁移完成后废弃  
- `schema_version`：**2 → 3**；加载旧档补默认字段，**不删除**未知字段；`>3` 拒绝加载  

### 3.3 `count` 语义

- 大地图 `count > 1`：目标 HP 池按编队结算；**禁止**在管线外另乘一套人数系数  
- 演武默认 `count = 1`；若场景使用编队，走同一 HP 池规则

## 4. CtxBuilder（修正组装）

### 4.1 职责

将下列来源的攻/防修正组装为 `atk_ctx` / `def_ctx` 字典，供 `CombatResolver.compute_damage` 使用。

| 来源 | 攻 | 防 | 查询 API（只读） |
|:---|:---:|:---:|:---|
| 地形 | ✓ | ✓ | `terrain.json` atk_mod / def_mod |
| 科技 | ✓ | ✓ | `TechSystem.get_attack_modifier` / `get_defense_modifier` |
| 学派 | ✓ | ✓ | SchoolManager 战斗效果 |
| 武大夫 | ✓ | — | `MinisterManager.get_faction_military_attack_bonus` |
| 国家民心 | ✓ | — | `GameManager.get_morale_threshold_effect` |
| 粮荒 | ✓ | ✓ | `GameManager.get_grain_shortage_*` |
| 单位被动技能 | ✓ | — | UnitState.skills |
| 火攻/伏击 | ✓ | — | 季节 + 地形判定 |
| 单位士气四段 | ✓ | ✓ | `CombatResolver` 内部 |

### 4.2 规则

1. **大地图与演武必须调用同一 CtxBuilder**  
2. 来源系统为**大地图权威**，演武实时只读，不写回  
3. 禁止在 Manager 内手拼另一套 ctx  
4. 未传 ctx 时 `CombatResolver` 按空修正计算——**仅允许用于单元测试**，生产路径必须传

## 5. CombatPipeline（攻击阶段机）

### 5.1 阶段顺序

```
预检（适配层） → 伤害 → 反击 → 夹击/包围士气 → 火攻 DOT → 状态写回
```

| 阶段 | 内容 | 归属 |
|:---|:---|:---|
| **预检** | 阵营相同？acted？距离/射程（含遮挡）？MP？**宣战？** | **适配层** |
| 伤害 | `CombatResolver.compute_damage` + ctx | 纯内核 |
| 反击 | 远程主动攻击默认无反击；近战反击见《战斗系统》 | 纯内核 |
| 士气 | 夹击 -15 / 包围 -30；崩溃独立乘算 | 纯内核 |
| 火攻 | 夏秋 + 特定地形；DOT `burn_turns` | 纯内核 |
| 写回 | hp/morale/burn/acted/mp | 适配层 |

### 5.2 宣战门闩（大地图专属预检）

- 大地图：`DiplomacySystem.are_at_war` 不通过则 **拒绝攻击**（决策 #89）  
- 演武：场景预设敌对，**跳过**宣战检查  
- 门闩**不得**写进纯内核，避免单元测试与演武被外交状态污染  

### 5.3 输出

统一返回结构：

```
{ ok, reason, damage, counter_damage?, fire?: bool, morale_delta_atk?, morale_delta_def? }
```

## 6. MovementReach（可达格）

统一计算：

| 因素 | 说明 |
|:---|:---|
| 地形 `move_cost` | 天堑未解锁为不可达 |
| 骑兵/水军限制 | `cavalry_allowed` / `is_navigable` |
| ZOC | 敌方控制区额外消耗 |
| 远程遮挡 | 高程差减射程（攻击用） |
| 城墙挡格 | 未破墙不可停留 |
| 搁浅 | 水域规则 |
| MP | 本回合剩余行动力 |

大地图与演武共用同一 reach 实现；地图边界由适配层裁剪。

## 7. SiegeResolver（攻城）

### 7.1 统一规则

- 城墙/箭塔：结构 HP，来自 `buildings.json` + `balance_params.fortification`  
- 器械对城防倍率：`city_combat.siege_damage_multiplier`  
- 驻进城防反击：见《战斗系统》城防节  
- 城防 HP 归零 → 占城（适配层调用 `CityManager.change_ownership`）  

### 7.2 城墙运行时状态归属

- **权威存储**：`CityManager`（墙 HP 可入存档）  
- 演武内存字典仅为场景缓存，结束时同步或丢弃（Demo 写回路径除外）  

### 7.3 中立城

- 大地图：玩家可攻中立；AI 默认不攻中立  
- 演武：按场景配置

## 8. AI Scoring

| 档位 | 用途 | 行为 |
|:---|:---|:---|
| `scored` | 大地图 / 正式演武 | 目标评分、残血优先、器械攻城、ZOC 风险 |
| `tutorial` | 教学演武默认 | 弱化/引导，不用完整评分 |
| `random` | 测试/兼容 | 现网随机 |

大地图额外约束：每回合单位预算、仅战争目标。

## 9. 文化与外交在演武侧

| 系统 | 演武行为 |
|:---|:---|
| 文化扩散/主流变更 | **不跑** |
| 文化 mismatch | 需要时**只读** `CityManager.has_culture_mismatch`；若进战斗只经 def ctx |
| 外交 AI/宣战/停战 | **不跑** |
| 科技/学派/大夫/粮荒 | CtxBuilder **实时只读** |
| 写回条约 | **不写** |
| Demo 占城写回 | `DemoFlow.apply_skirmish_victory` → `CityManager.change_ownership` |

## 10. 建造 API（经营统一入口）

```
can_build(city_id, building_id, axial: Vector2i = Vector2i(-9999,-9999)) -> Dictionary
start_build(city_id, building_id, axial: Vector2i = Vector2i(-9999,-9999)) -> bool
get_jurisdiction_hexes(city_id) -> Array[Vector2i]
```

Reason 契约见《城市经营》与决策 214；城池面板、大地图放置、EconomyAI、演武内放置共用。
