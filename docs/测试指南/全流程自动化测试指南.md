# 全流程自动化测试使用指南

> **更新日期**：2026-09-14  
> **适用对象**：策划 / 程序 / 测试  
> **目标**：任何人可在本机一键跑通全部回归，并知道失败时怎么定位。

---

## 1. 一键回归（推荐）

在**项目根目录**执行：

```powershell
powershell -File tools/run_auto_regression.ps1
```

可选参数：

| 参数 | 说明 |
|---|---|
| `-GodotPath "E:\path\to\Godot_console.exe"` | 指定 Godot 可执行文件（默认自动探测） |
| `-SkipGut` | 只跑冒烟，跳过 GUT 单元测试 |
| `-SkipSmoke` | 只跑 GUT，跳过冒烟 |

脚本会依次执行三步：

1. **资源导入**（`--import`）
2. **GUT 全量**：逐个跑 `tests/unit/test_*.gd`
3. **完整流程冒烟**：`tests/smoke/full_flow_smoke.gd`

日志目录：`.auto_regression/`（已 gitignore）

| 文件 | 内容 |
|---|---|
| `summary.txt` | 汇总结果（先看这个） |
| `test_xxx.log` / `.log.err` | 单个 GUT 套件输出 |
| `smoke.log` / `.log.err` | 冒烟输出 |

**判定**：

- 控制台出现 `ALL GREEN` → 退出码 0，全部通过
- 出现 `HAS FAILURES` → 退出码 1，按 `summary.txt` 里的 `[FAIL]` 套件名查对应 log

**注意**：`test_main_turn_ui` 较慢（约 9 分钟，含 await + 多轮 AI），属正常现象，不是卡死。

## 2. 单独跑某个 GUT 套件

调试时不必跑全量。在项目根目录：

```powershell
$godot = "E:\programs\Godot_v4.3-stable_mono_win64\Godot_v4.3-stable_mono_win64_console.exe"
$root = "E:\Mountains_Rivers-The_Warring_States"
$args = @(
  "--headless","--path",$root,
  "-s","addons/gut/gut_cmdln.gd",
  "-gdir=res://tests/unit",
  "-gprefix=test_diplomacy_blocs.gd",
  "-ginclude_subdirs=0",
  "-gexit","-glog=1"
)
Start-Process -FilePath $godot -ArgumentList $args -NoNewWindow -Wait
```

把 `-gprefix` 换成目标文件名即可。

**常用套件对照**：

| 前缀 | 覆盖范围 |
|---|---|
| `test_diplomacy_system.gd` | 质子/俘虏/附庸/情报力/存档往返 |
| `test_diplomacy_blocs.gd` | 合纵/连横、战争借口、复国主义 |
| `test_tribute_enfeoffment.gd` | 朝贡冷却/册封一次性/方伯减罚/建筑外交 |
| `test_visibility_special_victory.gd` | 单位信息可见性、特殊胜利、i18n 键 |
| `test_event_conditions_i18n.gd` | tribute/reputation/hezong 条件、驿馆情报 |
| `test_game_manager.gd` | 回合状态机/资源/胜利（102 项，较慢） |
| `test_main_turn_ui.gd` | 主回合 UI（38 项，最慢） |
| `test_strategic_map_manager.gd` | 大地图单位生产/移动/攻击 |
| `test_save_manager.gd` | 多槽存档 |

## 3. 单独跑全流程冒烟

```powershell
$godot = "E:\programs\Godot_v4.3-stable_mono_win64\Godot_v4.3-stable_mono_win64_console.exe"
$root = "E:\Mountains_Rivers-The_Warring_States"
Start-Process -FilePath $godot -ArgumentList @(
  "--headless","--path",$root,"-s","res://tests/smoke/full_flow_smoke.gd"
) -NoNewWindow -Wait
```

**退出码**：`0` = 全过（当前期望 `PASS=47 FAIL=0`）；`1` = 有失败。

### 冒烟覆盖的 14 条路径

| 模块 | 验证点 |
|---|---|
| 数据 | 50 城 / 19 兵种 / 11 地形 / 科技 / 学派 JSON 可读 |
| 开局 | `start_game`、玩家首回合、资源初始化 |
| 经济 | 税率、产出、维护、人口/粮食 |
| 征兵 | 征兵池 → 战略单位生成 |
| 战略战 | 未宣战返回 `NOT_AT_WAR`；宣战后可攻击并造成伤害 |
| 外交 | 宣战 / 停战 / 战力评分 |
| 科技 | 研究接口可调用 |
| 学派/大夫 | 政策/派驻接口 |
| 奇观 | 开工与完工归属 |
| 存档 | 写槽 3、读回、自动槽 |
| Demo | 洛邑目标、占城 |
| 事件 | save 字典非空、系统存活 |
| 演武 | 激活、有单位、胜利检查 |
| 回合 | 势力切换、推进、AI 一轮后存活 |

### Autoload 注意

冒烟用 `-s` 启动，**不能**依赖全局类名，必须：

```gdscript
var _gm = root.get_node_or_null("/root/GameManager")
```

写新冒烟用例时请沿用此模式。

## 4. 失败怎么排查

1. 打开 `.auto_regression/summary.txt`，找 `[FAIL]` 行。
2. 打开同名 `.log`，搜 `Failed` / `SCRIPT ERROR` / `Parse Error`。
3. 若是 `SCRIPT ERROR`：通常是改了 API 签名或 JSON 字段，先修代码再跑。
4. 若是断言失败：log 里有断言消息（如 `reason=not_eligible`），对照源码定位。
5. 冒烟失败时优先看 `[SMOKE][FAIL]` 行的 detail。

**编辑器干扰**：若 Godot 编辑器开着并弹出「磁盘文件已更改」，先在编辑器里重新加载，避免旧缓冲把改动顶回去。CLI 测试不受影响。

## 5. 测试文件结构

```
tests/
├── unit/                    # GUT 单元测试（45 套件）
│   ├── test_*.gd
│   └── .gdignore            # 防止 Godot 扫描 tests 为场景资源
└── smoke/
    └── full_flow_smoke.gd   # API 级全流程冒烟（47 项）
```

新增单元测试规范：

- 文件名 `test_xxx.gd`，`extends GutTest`
- `before_each()` 里 reset 各 Manager 并 `start_game`
- 优先测**机制公式/状态机/存档往返**，不测 UI 像素
